# Pegel 0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ein KDE-Tray-Programm, das auf Klick die Kontingente aller KI-Coding-Konten aus `quota-axi` zeigt.

**Architecture:** Bauweise wie Hafen: Ein statisches QML-Modul `Pegel` enthält die C++-Typen (`Quota`, `Tray`, `Launcher`) und die QML-Oberfläche. Alles Rechnen und Entscheiden liegt in `src/model.mjs` und läuft unter Node und in Qts JavaScript-Engine. C++ startet nur Prozesse, liest Verzeichnisse und zeichnet das Tray-Icon.

**Tech Stack:** C++20, Qt ≥ 6.5 (Core, Gui, Widgets, Qml, Quick, QuickControls2, QuickTest, LinguistTools), KF6 Kirigami, KF6 StatusNotifierItem, KF6 DBusAddons, CMake, CPack, Node für die Modelltests.

**Spec:** `docs/superpowers/specs/2026-11-24-pegel-design.md`

**Vorlage:** Hafen im Nachbarordner `../hafen`, Zweig `feature/ui-tests`. Wo eine Aufgabe „wie Hafen“ sagt, wird die genannte Hafen-Datei übernommen und `hafen`/`Hafen`/`HAFEN` durch `pegel`/`Pegel`/`PEGEL` ersetzt. Der SPDX-Kopf jeder Datei lautet `GPL-3.0-or-later`, Urheber „Pegel contributors“.

## Global Constraints

- Name „Pegel“, Programm `pegel`, App-ID `io.github.bdgraue.Pegel`, QML-Modul `Pegel`, Einstellungen in `~/.config/pegel/pegel.conf`, Version 0.1.0.
- Alle Zahlen kommen aus `quota-axi --json --full`. Pegel ruft keine Anbieter-API auf und liest keine Zugangsdaten.
- `--allow-keychain-prompt` und `--allow-claude-inference` werden nie übergeben.
- Ein Fenster ohne `percentUsed` zeigt „—“ und nie „0 %“.
- `schemaVersion` muss 5 oder 6 sein, alles andere ist ein Lesefehler.
- Öffentliches Repository: Testdaten, Dokumente und Commit-Texte nennen nur `example.com` und erfundene Namen, kein Pfad beginnt mit einem echten Home-Verzeichnis. Das Repository enthält keine Anbieter-Logos.
- `src/model.mjs` nutzt weder Objekt-Spread noch `Array.prototype.flatMap` noch destrukturierte Parameter in Sortierfunktionen.
- Quelltexte der Oberfläche sind englisch mit `qsTr`. README und Changelog sind deutsch.
- Fremde Symbole (Qt, KF6, Kirigami) werden vor der Verwendung in den Headern unter `/usr/include` oder in `../hafen` nachgeschlagen.
- Commits nur, wenn der Nutzer sie freigegeben hat. Betreffzeilen kurz und deutsch wie in Hafen.
- Stufen: 0 unter 60 %, 1 ab 60 %, 2 ab 80 %, 3 ab 92 %.
- Zeiten: Lesen alle 5 Minuten (einstellbar 1 bis 60), beim Öffnen nach 60 Sekunden, 30 Sekunden nach einem Reset, Zeitlimit 60 Sekunden. Alt ist ein Stand nach zwei Leseintervallen.

## Review Focus

1. Die Login-Shell schreibt vor oder nach dem JSON eigenen Text. Erwartet: Pegel liest das JSON trotzdem. Test in Aufgabe 2 (`extractJson`).
2. Der Rechner war im Ruhezustand. Erwartet: Nach dem Aufwachen liest Pegel sofort, statt bis zu 5 Minuten alte Zahlen als frisch zu zeigen. Test in Aufgabe 5 (`readDue`) und 8.
3. `percentUsed` liegt über 100 oder unter 0. Erwartet: Der Text zeigt den gemeldeten Wert, der Balken bleibt in seinen Grenzen. Test in Aufgabe 3.
4. Ein Profilordner enthält einen Doppelpunkt, das Trennzeichen von `QUOTA_AXI_CLAUDE_PROFILES`. Erwartet: Pegel lehnt den Ordner mit Begründung ab, statt zwei falsche Pfade zu übergeben. Test in Aufgabe 6.
5. `pegel.conf` enthält in einem JSON-Feld Unlesbares. Erwartet: Pegel startet, nennt das Feld im Fenster und überschreibt es erst, wenn der Nutzer die Einstellung ändert. Test in Aufgabe 6 (`parseSetting`) und 10.

## Gemeinsame Typen

Zeitpunkte sind Millisekunden seit 1970, `null` heißt unbekannt. Texte sind `""`, wenn sie fehlen.

```
Report  { readAt, lanes: Lane[] }
Lane    { key, provider, label, plan, status, notSetUp, refreshedAt,
          error, reason, remedyCommand, retryAfter, profileDir,
          email, organization,
          credits: { remaining, unlimited, unit } | null,
          runway: { status, remaining, exhaustedAt, freeAt, confident } | null,
          windows: Window[] }
Window  { id, label, kind, percentUsed, resetsAt, startsAt, cycleSeconds,
          shareOf, untrusted, exhaustedAt,
          amount: { used, limit, unit } | null }
Options { hidden: string[], names: { [key]: string },
          kinds: { session, weekly, monthly, model, other },
          showNotSetUp, notify, threshold, refreshMs }
```

`kinds.other` deckt die Arten `credits` und `unknown` ab und ist in der Vorgabe an. Die Spec nennt vier Arten; die fünfte ist nötig, weil OpenCode Go sein 5-Stunden-Fenster als `unknown` meldet.

Die Modelltests benutzen `const NOW = Date.parse("2026-01-15T12:00:00Z")`. `tests/setup.mjs` setzt `process.env.TZ = "UTC"`, `tests/ui/main.cpp` setzt `TZ=UTC` per `qputenv` vor dem Anlegen der Anwendung.

- Produces: `SCHEMA_VERSIONS = [5, 6]`, `STATUSES = ["fresh", "stale", "unavailable", "auth_required", "rate_limited", "error"]`.

Regeln für `parseReport`:

- `key` ist `provider + "/" + (accountKey ?? "default")`.
- `refreshedAt` ist `state.refreshedAt`; fehlt es bei Status `fresh`, gilt `readAt`.
- `profileDir` ist `accountLocator.path`. Zeilen, deren `profileDir` in `disabledDirs` steht, entfallen.
- `runway` kommt aus dem Bereich `all_models`, wenn dessen `status` `known` ist: `remaining` ist `effectivePercentRemaining`, `exhaustedAt` ist `runway.projectedExhaustedAt`, `confident` ist `projectionConfidence === "established"`, `freeAt` ist `resetsAt` des Fensters `runway.limitingWindowId`. Sonst `null`.

### Task 3: Ein Limit-Fenster darstellen

**Files:**
- Modify: `src/model.mjs`
- Test: `tests/model.cases.mjs`

**Interfaces:**
- Consumes: `Lane`, `Window`, `level`.
- Produces: `until(ms: number): string`, `ago(ms: number): string`, `clock(at: number, now: number): string`, `isOld(lane, now, refreshMs): boolean`, `windowView(lane, window, now, refreshMs): WindowView`.

```
WindowView { label, percentText, fill, level, elapsed, detail, dimmed, indent }
```

Regeln:

- `until`: „18 min“, „1 h 18 min“, „2 d 5 h“. `ago`: „just now“ unter einer Minute, „12 min ago“, „3 h ago“, „2 d ago“.
- `clock`: am selben Kalendertag „22:37“, an einem der nächsten sechs Tage „Wed 22:37“, danach „in 12 d“. Die Wochentagskürzel gehen einzeln durch `qsTr`.
- `isOld`: Status `stale`, oder `refreshedAt` ist `null`, oder `now − refreshedAt > 2 × refreshMs`.
- `label`: „%1 hours“ mit `Math.round(cycleSeconds / 3600)` für `session` (ohne Zyklus 5), „Week“ für `weekly`, „Month“ für `monthly`, sonst `window.label`. Haben zwei Fenster des Eintrags dieselbe Art, gilt für beide `window.label`.
- `percentText`: `Math.round(percentUsed) + " %"`, ohne Wert „—“. `fill` ist `percentUsed / 100`, begrenzt auf 0 bis 1, ohne Wert `null`. `level` ohne Wert `null`.
- Der Reset ist bekannt, wenn `resetsAt` nicht `null` ist und nach `lane.refreshedAt` liegt. Er ist vorbei, wenn er bekannt ist und nicht nach `now` liegt.
- `elapsed`: `1 − (resetsAt − now) / (cycleSeconds × 1000)`, begrenzt auf 0 bis 1; `null` ohne Zyklus, ohne bekannten Reset oder nach dem Reset.
- `detail`, Teile mit „ · “ verbunden, in dieser Rangfolge:
  1. `untrusted`: nur „not trusted by quota-axi“.
  2. Reset vorbei: nur „no new reading since the reset“.
  3. Ohne `percentUsed`: der Betrag als „12.40 of 50.00 $“, sonst leer. Das Dezimalzeichen geht als eigener Text `qsTr(".")` durch die Übersetzung.
  4. Sonst: „resets in %1“ bei bekanntem Reset; die Tempo-Angabe, wenn `elapsed` mindestens 0,03 ist; bei Art `model` „empty around %1“, wenn `exhaustedAt` zwischen `now` und `resetsAt` liegt.
- Tempo: `d = Math.round(percentUsed − elapsed × 100)`; unter 5 Punkten Abstand „on pace“, sonst „%1 % over pace“ oder „%1 % under pace“.
- `dimmed`: `untrusted`, Reset vorbei oder `isOld(lane)`. `indent`: `shareOf` ist gesetzt.

### Task 4: Einträge

**Files:**
- Modify: `src/model.mjs`
- Test: `tests/model.cases.mjs`

**Interfaces:**
- Consumes: `Report`, `Lane`, `Options`, `clock`, `ago`, `isOld`.
- Produces: `laneNames(lanes, names): { [key]: string }`, `visibleLanes(report, options): Lane[]`, `notSetUpCount(report): number`, `laneSummary(lane, now): string`, `laneProblem(lane, now): { text, command } | null`, `laneAge(lane, now, refreshMs): string`, `creditsText(lane): string`, `planText(lane): string`.

Regeln:

- `laneNames`: Der Name ist `label`. Hat ein Eintrag einen eigenen Namen in `names`, oder teilen sich mehrere Einträge den Anbieter, lautet er `label + " · " + Zusatz`. Zusatz ist der eigene Name, sonst aus `profileDir`: Ordnername `.claude` wird „Default“, `.claude-<x>` wird `<x>`, jeder andere Ordnername bleibt. Ohne `profileDir` ist der Zusatz der Teil des Schlüssels nach dem Schrägstrich.
- `visibleLanes`: nicht in `options.hidden`, und `notSetUp` nur bei `options.showNotSetUp`. Reihenfolge wie geliefert.

Regeln:

- Ein Fenster zählt, wenn sein Eintrag sichtbar, eingerichtet und nicht alt ist, es einen `percentUsed` hat, kein `shareOf`, nicht `untrusted`, sein Reset nicht vorbei ist und seine Art in `options.kinds` angehakt ist (`credits` und `unknown` unter `other`).

- `notifications`: `memory` ist `{ primed, cycles: { "<key>|<id>": { resetsAt, warned, exhausted } } }`, Anfangswert `{ primed: false, cycles: {} }`. Der erste Aufruf merkt sich nur den Stand, `warned` und `exhausted` gelten dabei als schon gemeldet, soweit erreicht. Danach je gezähltem Fenster: Hat sich `resetsAt` geändert, beginnt ein neuer Zyklus; war der alte `exhausted` und liegt der neue Wert unter 100, kommt „available again“. Erreicht der Wert 100 und war `exhausted` falsch, kommt „used up“; dabei gilt auch `warned` als gemeldet. Erreicht er sonst `options.threshold` und war `warned` falsch, kommt die Warnung. Bei `options.notify === false` bleibt `messages` leer, `memory` läuft weiter.
- Meldungen: Titel ist der Name des Eintrags. Texte „%1 at %2 %“ (Icon `dialog-warning`), „%1 used up, free from %2“ oder ohne Reset „%1 used up“ (Icon `dialog-warning`), „%1 available again“ (Icon `io.github.bdgraue.Pegel`). `%1` ist das `label` aus `windowView`.
- `nextResetRead`: der früheste bekannte, künftige `resetsAt` eines Fensters, das bis auf die Reset-Prüfung zählt und `options.threshold` erreicht hat, plus `RESET_READ_DELAY_MS`.
- `readDue`: `now − lastAttemptAt >= refreshMs`. Die Leseschleife prüft das alle 30 Sekunden, statt einen Timer über das ganze Intervall laufen zu lassen. Nach dem Ruhezustand ist ein Lesen so sofort fällig.
